# WB KIZ Exporter

Автоматическая выгрузка кодов маркировки (КИЗ) из Wildberries для вывода из оборота в системе Честный Знак.

## 📋 Описание

При работе по схеме FBS (Fulfillment by Seller) продавец обязан **самостоятельно выводить коды маркировки из оборота** в системе Честный Знак при дистанционной продаже товаров. Ручная выгрузка данных из личного кабинета Wildberries и формирование XML-файлов для ЧЗ занимает много времени и подвержена ошибкам.

**WB KIZ Exporter** автоматизирует этот процесс: скрипт получает данные через API Wildberries, фильтрует только нужные продажи, извлекает КИЗы и формирует готовые XML-файлы для загрузки в Честный Знак.

## ✨ Возможности

- 🔄 Автоматическое получение списка FBS-заданий через API Wildberries
- 🎯 Фильтрация только проданных заказов (статус `wbStatus=sold`)
- 📦 Извлечение КИЗов из метаданных заказов
- 🗂️ Группировка КИЗов по поставкам (каждая поставка = отдельный XML)
- 🔁 Дедупликация через файл истории (повторные запуски не создают дубли)
- ⏱️ Защита от лимитов API (экспоненциальная задержка при 429)
- 📄 Генерация XML по схеме Честного Знака (version 8)
- 🔒 Безопасное хранение токенов через `.env`

## 🛠️ Технологии

- Python 3.9+
- `requests` — HTTP-запросы к API
- `python-dotenv` — управление переменными окружения
- `xml.etree.ElementTree` — генерация XML
- Wildberries Marketplace API
- Честный Знак (ГИС МТ)

## 🚀 Установка

### 1. Клонируйте репозиторий

```bash
git clone https://github.com/YOUR_USERNAME/wb-kiz-exporter.git
cd wb-kiz-exporter
```

### 2. Создайте виртуальное окружение

```bash
python -m venv .venv
.venv\Scripts\activate       # Windows
source .venv/bin/activate    # macOS/Linux
```

### 3. Установите зависимости

```bash
pip install -r requirements.txt
```

## ⚙️ Настройка

### 1. Создайте файл `.env`

Скопируйте `.env.example` в `.env`:

```bash
cp .env.example .env
```

> ⚠️ Файл `.env` добавлен в `.gitignore` — не коммитьте его в репозиторий.

### 2. Заполните данные

Откройте `.env` и укажите:

```env
# Токен API Wildberries
# Получить: ЛК WB → Настройки → Доступ к API → Создать токен
WB_TOKEN=ваш_токен_здесь

# ИНН вашей организации
SELLER_INN=123456789012

# ФИАС ID места осуществления деятельности (МОД)
# Найти: ЛК Честный Знак → Профиль участника оборота
SELLER_FIAS_ID=00000000-0000-0000-0000-000000000000
```

### 3. Настройте параметры (опционально)

В начале файла `wb_parser.py` можно изменить:

```python
DAYS_BACK = 90               # Период поиска заказов (дней)
USE_SHORT_KIZ = True         # Формат КИЗ: True = короткий (GTIN+SN), False = полный
HISTORY_RETENTION_DAYS = 90  # Сколько дней хранить историю
```

## 🏗️ Как это работает

### Архитектура

```text
┌─────────────────┐     GET /api/v3/orders      ┌─────────────────────┐
│                 │ ──────────────────────────► │                     │
│  wb_parser.py   │                             │  Wildberries API    │
│                 │ ◄────────────────────────── │                     │
└────────┬────────┘   JSON (список заданий)     └─────────────────────┘
         │
         │ POST /api/v3/orders/status
         ▼
┌─────────────────┐     JSON (статусы)          ┌─────────────────────┐
│  Фильтрация     │ ──────────────────────────► │  Проверка wbStatus  │
│  sold заказов   │ ◄────────────────────────── │  = "sold"           │
└────────┬────────┘                             └─────────────────────┘
         │
         │ POST /api/marketplace/v3/orders/meta
         ▼
┌─────────────────┐     JSON (метаданные)       ┌─────────────────────┐
│  Извлечение     │ ──────────────────────────► │  КИЗы заказов       │
│  КИЗов          │ ◄────────────────────────── │                     │
└────────┬────────┘                             └─────────────────────┘
         │
         ▼
┌─────────────────┐
│  Группировка    │ ─► XML-файлы по поставкам
│  по поставкам   │ ──► История обработанных КИЗов
└─────────────────┘
```

### Ключевые решения

1. **Дедупликация через историю** — файл `kiz_history.txt` хранит все обработанные КИЗы с датой. При повторном запуске скрипт пропускает уже выведенные коды.
2. **Защита от лимитов API** — при получении HTTP 429 (Too Many Requests) скрипт делает паузу с экспоненциальным ростом (30 → 60 → 120 сек) и повторяет запрос.
3. **Группировка по поставкам** — каждый XML содержит КИЗы только одной поставки (`supplyId`), что соответствует требованиям Честного Знака к первичным документам.
4. **Короткий формат КИЗ** — по умолчанию скрипт обрезает полный код маркировки до 31 символа (GTIN + серийный номер), как требует схема ЧЗ.

## 🔧 Решенные проблемы

В процессе разработки были решены следующие нетривиальные задачи:

1. **Лимиты API Wildberries** — реализована система повторных запросов с экспоненциальной задержкой.
2. **XSD-валидация Честного Знака** — точное соответствие структуры XML схеме версии 8.
3. **Дедупликация** — предотвращение повторного вывода одних и тех же КИЗов из оборота.
4. **Разделение схем FBS/FBO** — скрипт работает только с FBS-заказами (FBO выводит КИЗы автоматически).

## 🩺 Troubleshooting

| Проблема | Возможная причина | Решение |
|---|---|---|
| `401 Unauthorized` | Неверный или просроченный `WB_TOKEN` | Пересоздайте токен в ЛК WB → Настройки → Доступ к API |
| `429 Too Many Requests` | Превышен лимит API | Скрипт сам ждёт и повторяет; можно увеличить паузу в коде |
| Пустой список заданий | Нет проданных FBS-заказов за период | Увеличьте `DAYS_BACK` или проверьте, что работаете по FBS |
| КИЗы не найдены | В заказе нет метаданных с КИЗ | Проверьте, что товар маркируется и КИЗ привязан в ЛК WB |
| XML не проходит валидацию в ЧЗ | Неверный `SELLER_FIAS_ID` или `SELLER_INN` | Проверьте данные в профиле участника оборота ЧЗ |
